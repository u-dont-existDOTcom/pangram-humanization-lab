## 3. Audit of the repair explanation itself

The prior explanation overreached when it implied that a larger positive corpus would explain the entire failure. What is established is a retrieval and indexing gap: exact positive examples existed on task branches but were absent from the two-example default generator index. What is not established is that the two-example count uniquely caused poor generation, or that simply adding more examples will cure it.

Similarly, context saturation is a plausible contributor, not a directly measured internal mechanism. A fresh context changes several conditions. Its success or failure would not identify one unique cause without a controlled comparison.

The repaired system therefore separates three deliverables:

1. **Evidence recovery:** literal examples and labels are available, provenance-bound and usable.
2. **Applied development study:** examples have been compared, counterexamples have changed the working explanations, and a writer-facing packet exists.
3. **Prospective transfer:** a new candidate must demonstrate improvement on a new target with external review. This is not satisfied by the first two deliverables.
