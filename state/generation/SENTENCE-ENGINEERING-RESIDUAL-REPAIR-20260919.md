# Sentence engineering as residual-repair attractor

Date: 2026-09-19
Status: **ACTIVE ARCHITECTURE LESSON / HISTORICALLY SUPPORTED FOR RESIDUAL REPAIR / NOT SUFFICIENT ON ALL-RED PARAGRAPHS**

## Owner hypothesis

Joel proposed a useful cognitive framing:

Broad prose generation keeps the model inside its strong writing attractor.

A task framed as:
`how should this specific model sentence change?`
may instead move the model into an engineering/problem-solving attractor.

Historical Episode 007 already supported this:
holistic rewrites plateaued, then explicit sentence dispositions
`keep / rewrite / merge / delete-as-separate-sentence`
materially reduced detector-red content.

## Why this does not erase Episode 007

Episode 007 R8D/R8E/R8F had a different topology:

- large Human/high spans already existed;
- Pangram localized exact residual AI/high regions;
- the sentence guide targeted those residuals only;
- green text stayed byte-for-byte fixed;
- each pass narrowed edit scope;
- R8F changed one final 39-word residual next to a frozen 50-word Human/medium tail;
- Joel reported the final complete boundary Human/high, displayed 100%.

This suggests the engineering attractor is strongest when it is a **repair compiler**, not a replacement for the missing Human thought substrate of a wholly model-shaped paragraph.

## Active production rule

For difficult humanization:

1. Generate/obtain a concrete draft once.
2. Localize real failures using owner/editorial judgment and detector evidence when useful.
3. Freeze genuinely Human spans.
4. For each red sentence/span, create an engineering ticket:
   - exact current text;
   - disposition: keep / rewrite / merge / delete / move / subordinate;
   - causal defect;
   - protected function;
   - exact required structural change.
5. Execute only the ticket; do not ask the executor to redesign the section.
6. Integrate mechanically.
7. Run preservation.
8. Re-evaluate the paragraph/natural boundary.
9. Narrow again if a real green/red map exists.

## All-red stop rule

If essentially every sentence in a paragraph is model-shaped and repeated local patching only produces different model-shaped sentences:

- do not keep issuing more local tickets indefinitely;
- do not treat a lower detector probability with the same AI label as success;
- do not add more style prohibitions;
- change the substrate/composition architecture.

The engineering method requires something worth preserving around the repair.

## Durable-learning implication

Store **operation traces**, not only before/after prose:

`failed sentence -> causal diagnosis -> engineering disposition -> protected function -> exact local replacement -> integrated outcome`

This trace is more likely to reactivate the useful engineering mode than an abstract instruction such as `stay in the thinking process`.

But an operation trace is promoted to generator skill only after fresh transfer succeeds.
