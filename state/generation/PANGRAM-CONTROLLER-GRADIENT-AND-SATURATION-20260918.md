# Method lesson — detector controller needs a gradient; saturation means switch the generator

Date: 2026-09-18
Status: **ACTIVE HUMANIZATION METHOD LESSON**

## Evidence

Two adjacent Inner Child Therapy subsections behaved very differently under the same Pangram-GUI convergence controller.

### Also Look Outward

Measured model progression:
- Candidate F: AI 0.5329530835
- Candidate G: AI 0.4243027866
- Candidate H: AI 0.0 / Human 1.0

The controller had a usable gradient. Local edits produced measurable movement, so continuing the same loop was rational.

### Write It. Don't Send It Yet.

Six materially varied model realizations all returned:
- AI 1.0
- Human 0.0

The variants included:
- direct instructional rewrite;
- broader natural realization;
- two-job abstraction;
- source-grounded reader situation;
- single concrete editing scene;
- oral-friend intermediate.

No Human island emerged.

## Lesson

Pangram can function as an active convergence controller only when the generator family exposes a usable gradient.

If repeated materially different candidates all saturate at essentially the same detector state:
- stop treating another rewrite as the next experiment;
- do not keep spending detector calls;
- infer that the current generator family/representation is not producing the variation the controller needs;
- switch composition architecture before resuming measurement.

The detector is not a magic humanizer. It is a feedback signal.

A controller with no gradient cannot steer.

## Production rule

During detector-guided humanization:

1. if successive exact candidates show directional movement, keep the loop tight and continue;
2. if results are flat after materially different edits, stop the loop at the section's call budget;
3. preserve all exact results;
4. compare structurally different generator architectures before another paid/credit-bearing measurement;
5. never reset the call counter merely because the method changed.
