# Generator learning compiler v1

Date: 2026-09-19
Status: **ACTIVE GENERATION ARCHITECTURE / OWNER-CORRECTED**

## Why this exists

The humanization program has repeatedly recognized the same fact:

> Human writing often remains inside the thinking process itself instead of collapsing the thought into a polished semantic summary.

That recognition has been stored many times, yet fresh generation still often returns to:
- one-function-per-sentence advancement;
- conceptual compression;
- explanatory aftercare;
- tidy balanced contrasts;
- complete mini-lessons.

That means the durability problem is not only **lesson storage**.

It is a **knowledge-to-behavior compilation failure**:
the project has been getting better at remembering and criticizing the failure without reliably changing the generator that produces it.

## Core distinction

Never use `learned` as one undifferentiated state.

A lesson can be:

1. **OBSERVED**
   - owner or detector reveals a failure/success;
2. **EXPLAINED**
   - critic can name the mechanism;
3. **REPRODUCED_FROM_OWNER**
   - model can preserve/minimally normalize owner Human thought;
4. **TRANSFERRED_ONCE**
   - model generates fresh wording on a different target and succeeds;
5. **TRANSFERRED_TWICE**
   - success repeats on another target/rhetorical job;
6. **PRODUCTION_SKILL**
   - transfer survives owner editorial judgment + valid paragraph-level evidence and is reliable enough to activate by default.

Only stages 4–6 are evidence that the **generator** learned.

Owner rewriting, near-verbatim cleanup, anchor masking, or same-target detector optimization cannot promote a lesson above stage 3.

## Mandatory compile loop after every useful owner correction

Every useful teaching event must update four objects, not merely another prose lesson:

### A. Literal episode

Store:
- failed model prose;
- exact owner correction/rewrite when supplied;
- exact provenance;
- alignment class;
- detector/editorial outcome if decision-relevant.

### B. Generative delta

Write one short statement answering:

**What must the generator do differently while composing, before there is prose to criticize?**

This must be an operation on thought formation, not a blacklist.

Bad:
- avoid polished prose;
- do not overcompress;
- do not say `the thing`.

Better:
- stay with the writer's unresolved local concern for another beat before abstracting it;
- allow a lived contradiction to remain unresolved instead of immediately reconciling both sides;
- follow the order in which a person notices/changes their mind rather than the order of the preservation ledger;
- let one concrete social act carry several source functions instead of assigning one sentence to each.

### C. Counterfactual transfer target

Before calling the lesson learned, identify a fresh target where the same generative delta should help **without copying owner wording**.

The transfer target must differ enough that phrase imitation cannot explain success.

### D. Promotion result

Record:
- did fresh generation change?
- did it preserve meaning?
- did owner editorial judgment accept it?
- did paragraph-level detector evidence pass where valid?

If transfer fails, the lesson remains diagnostic. Do not add another prohibition and pretend the generator learned.

## Writer activation contract

Before a new Joel-byline generation task, do **not** load the entire archive of failures.

Instead:

1. identify the target's rhetorical job;
2. retrieve 2–4 literal episodes with the closest **thought-formation problem**;
3. retrieve the current promoted generative deltas;
4. build a tiny target-local composition state:
   - what is the live thought?
   - what tension is still unresolved?
   - what would a person notice/say/do next?
   - what source functions can ride inside that movement?
   - what should remain unsummarized for now?
5. generate from that state;
6. only afterward run preservation and anti-pattern audit.

The preservation ledger is a post-generation proof, not the writer's outline.

## The current promoted generative deltas

These are active as **hypotheses**, with skill stage shown.

### GD-001 — Stay inside the thought before summarizing

Stage: **EXPLAINED / transfer not yet established**

Human prose often retains:
- self-correction;
- partial uncertainty;
- lived contradiction;
- uneven thought duration;
- an ordinary social reaction;
before it converts experience into a conclusion.

Generator operation:
**continue the local thought one beat longer before abstracting it.**

Do not simulate this with fake hesitation, filler, random asides, or deliberate errors.

### GD-002 — Compose by human attention order, not preservation-unit order

Stage: **EXPLAINED / transfer not yet established**

Generator operation:
follow the order a person would actually notice:
event -> reaction -> correction -> unresolved concern -> maybe conclusion.

Do not assign one sentence per protected semantic unit.

### GD-003 — Let one lived move carry several functions

Stage: **EXPLAINED / transfer not yet established**

A real example, question, admission, or change of mind can satisfy several source obligations naturally.

Generator operation:
look for the smallest real social/cognitive move that carries multiple functions before creating separate explanatory sentences.

### GD-004 — Preserve unresolved tensions

Stage: **EXPLAINED / strong owner evidence, transfer not yet established**

Examples:
- directness can feel like honesty and still sometimes need repair;
- an apology can be real without erasing the original complaint;
- a person can be angry and still have a legitimate protest.

Generator operation:
do not resolve the tension merely to make the paragraph feel complete.

### GD-005 — Metaphor can remain partially unexplained

Stage: **EXPLAINED / strong owner evidence, transfer not yet established**

The owner image:
`holding his hand and showing him a better way, not stealing his pencil`
already carries relationship, agency, care, guidance and non-rejection.

Generator operation:
when a metaphor is doing real cognitive work, continue from what it makes possible rather than translating every component into counselor prose.

## Promotion discipline

A new lesson is not automatically added to the active writer reference.

Promotion requires:
- literal evidence;
- a generative delta;
- at least one transfer attempt.

A rule that has only critic evidence stays in the diagnostic layer.

Two successful fresh transfers on different targets are required before calling a generative delta a **production skill**.

## Anti-accumulation rule

If the active generation environment keeps growing because every failure adds another prohibition, stop.

That is evidence the critic is learning faster than the generator.

At that point:
- compress diagnostic rules into retrieval tags;
- keep only promoted generative deltas active;
- move failure-specific details back into literal episodes;
- test a new composition architecture rather than adding another rule.

## Current program diagnosis

As of 2026-09-19:

This status is intentional. Do not overclaim learning progress.

## 2026-09-19 architecture amendment — engineering attractor

Broad generation remains a strong failure mode on difficult Joel-byline prose. Activate `state/generation/SENTENCE-ENGINEERING-RESIDUAL-REPAIR-20260919.md` whenever a concrete model-shaped draft exists and failures can be localized.

Preferred repair representation is now the **operation trace**:
`exact failed sentence/span -> causal diagnosis -> keep/rewrite/merge/delete/move/subordinate -> protected function -> local replacement -> integrated outcome`.

Use this for residual repair around earned Human spans. Do not misapply it as an endless sentence-paraphrase loop when an entire paragraph is red; the 2026-09-19 Railway comparison showed that even fully isolated local patch executors can keep producing model-shaped patches without a Human substrate.


## 2026-09-19 strong-idea checkpoint — substrate + exemplar engineering both failed

Two materially different ideas were tested after Joel explicitly relaxed the six-call ceiling for high-information GUI experiments:

1. **Internal-cognition substrate**: switch from expository essay generation to literal self-questioning / changing-attention prose. Result: Pangram AI 1.0.
2. **Exemplar-conditioned sentence engineering**: give the executor exact historically successful before/after operation traces, then apply local structural operations to the unresolved Write It. Don't Send It Yet paragraph. Result: Pangram AI 1.0.

Both were exact-byte paragraph-level GUI checks.

Implication:
- do not continue nearby prompt variants on these architectures;
- the current bottleneck is deeper than missing slogans, missing local operations, or missing thought-process framing;
- wait for / use a materially different inference substrate or model execution path before more detector spend on the same generation prior;
- once Joel's explicit CLI inference backend on Railway is available, use it for controlled fresh-model comparisons rather than the project-scoped Railway Agent.
