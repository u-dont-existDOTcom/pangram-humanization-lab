## Process error after saturation

After the all-red result, the program increasingly treated each failure as a reason to invent another whole-paragraph generation architecture.

That drift moved away from the strongest successful pattern:
- keep one boundary stable;
- preserve anything genuinely good;
- make the smallest next generation/edit decision;
- use external or owner editorial feedback immediately;
- do not rebuild the entire passage after each failure.

The correct response to an all-red initial boundary is not necessarily another whole-paragraph prompt. It is to create the first reliable good island by a different **construction granularity**, then return to the proven convergence loop.

## Next architecture: progressive forward construction

When a target has no earned Human region:

1. keep the accepted preceding article context fixed;
2. generate only the next natural cognitive/social beat, not a complete paragraph or full preservation ledger;
3. judge that beat editorially before extending it;
4. once a beat is accepted, freeze it exactly;
5. generate the next beat from the accepted prefix;
6. continue until there is a paragraph-sized natural boundary;
7. run preservation across the assembled boundary;
8. Pangram the complete boundary only when editorially plausible;
9. if Pangram localizes red residuals, switch directly into the proven red-region repair controller.

This is **forward construction with a frozen accepted prefix**, the constructive analogue of the successful residual-repair process.

It preserves the owner's real goal: all publication wording can still be model-generated. Joel is not required to reauthor the passage; his/editorial judgment supplies acceptance feedback, not source prose.
