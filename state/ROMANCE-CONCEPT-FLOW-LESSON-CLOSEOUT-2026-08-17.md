# Romance Concept-Flow Lesson Closeout — 2026-08-17

## Case result

The Aug. 17 Romance improvement pass repaired several apparently local prose problems by first tracing each concept through **first seed -> primary explanatory home -> later application**. This prevented three recurrent mistakes:

1. adding a generic framework for a concept the article already demonstrated in distributed form (`honesty/privacy/timing`);
2. moving a practical examination upstream when only a setup bridge was missing (`idealization -> dependability -> flaws`);
3. treating a later callback as a new doctrine instead of checking whether it weakened an earlier threshold (`Nobody has to be completely healed` versus the categorical readiness floor).

## Transferable lesson promoted from the case

Before deciding a concept is missing or duplicated, trace its article-order lifecycle:

- first seed;
- primary home;
- later applications/callbacks;
- what a reader must already understand at each point.

Then classify the actual defect before adding prose. Prefer a transition or small seed over duplicated exposition when the full mechanism already has a good later home. Conversely, a later callback that appears to soften or contradict an earlier categorical premise should be repaired at the callback rather than by weakening the premise.

This extends, rather than replaces, the existing architecture/coherence rules: inspect upstream logic before downstream glue; do not answer questions the reader no longer has; and do not complete conceptual space merely because it can be completed.
