# `state/` Agent Instructions

- Treat current-state files as routing documents and lesson indexes/ledgers as durable learning controls; do not conflate them.
- Before trusting a checkpoint or summary, inspect actual Git state, current `LESSON-INDEX.md`, exact evidence refs/hashes, and newer owner instructions; repair stale entries immediately.
- Preserve passage-specific evidence, rejected variants, owner locks, and semantic dispositions. Do not turn one detector result into a universal phrase rule.
- Record completed work not to repeat, current step, last verified durable boundary, remaining work, blockers, exact evidence/tests/commits, and next safe action.
- Never store detector credentials, confidential text beyond its approved canonical location, secret values, private chain-of-thought, or large raw logs in checkpoint files.
- Distinguish verified, provisional, article-specific, superseded, and no-new-lesson findings.
- A checkpoint never outranks current owner instruction, exact article/project state, lesson-integrity evidence, or tests.
- After interruption or a fresh thread, identify exactly what survived and resume without repeating completed valid work.
