# Evidence-package runtime ownership repair — 2026-08-11

## Target-machine finding

During the in-place upgrade to the Pangram credential/self-heal release, release baseline reconciliation stopped on:

`AUTHORIAL-FLOW-EVIDENCE-bounded-failure-20260811-182825.zip`

The file was generated by Authorial Flow itself after a bounded repair failure. Older releases wrote evidence ZIPs at repository root. The release reconciler correctly rejected arbitrary untracked root files, but it could not distinguish this runtime-owned evidence artifact from an unrelated user edit. The same root-level ZIP would also make later Codex repair promotion reject the main worktree as dirty.

## Repair

- New evidence packages are written under ignored `.state/evidence/` rather than repository root.
- Before evaluating Git cleanliness, release reconciliation scans legacy root-level `AUTHORIAL-FLOW-EVIDENCE-*.zip` files.
- A legacy ZIP is migrated only when `PACKAGE.json` declares `authorial-flow-evidence-v1`, the reason is recognized, `SHA256SUMS.txt` exactly covers the package payload, and every listed SHA-256 verifies.
- A filename match alone is insufficient. Invalid or unrelated ZIPs continue to block release reconciliation.
- Existing checkpoint/thread/runtime state remains under `.state` and is not committed into the release baseline.
